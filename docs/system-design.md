# Solo Unicorn：行业经验访谈与求职福利入口

状态：当前产品定义，尚未实现或上线。第一期优先验证高质量获客、行业问题采集和用户获得的实际价值；课程、社区、专家合作与收费后续展开。

## 1. 产品定位

用户分享自己的工作经验，得到技能重评、可编辑和下载的优化简历、求职行动建议，以及可用的 AI／求职工具福利。平台获得有来源的职业背景、领域知识、具体行业问题，以及本人选择允许的后续联系渠道。

候选对外表达：**Turn your experience into a stronger resume and your next opportunity.**

入口同时说明：对话帮助用户整理求职材料；用户可以选择让有关流程和问题的回答用于 Solo Unicorn 的产品研究。求职服务、研究、社区、课程营销和专家回访分别记录用途。第一期不以课程成交为上线门槛。

| 用户得到 | 平台得到 | 同一访谈如何产生价值 |
|---|---|---|
| 技能重评 | 实际任务、职责和成果证据 | 真实案例支持能力描述 |
| 优化简历 | 经本人确认的职业背景 | 补齐事实后再润色 |
| 求职方向和资源 | 目标岗位、地区、语言与工作偏好 | 明确目标后才能有针对性改写 |
| AI／求职工具福利 | 工具兴趣及兑换反馈 | 按目标与地区匹配，不默认交出简历 |
| 后续同行或合作机会 | 分用途的联系意愿和领域标签 | 课程、社区、专家回访独立选择 |

技能报告是基于经历的重新梳理，不是能力认证、心理测验或就业预测。领域档案表示用户自述的经验及证据，不自动构成已核验的专家资格。

## 2. 首期范围

重点人群仍为约 35–50 岁、有传统行业经验、经历岗位变化的人；年龄不作为访问门槛或质量分数。先选择容易触达的行业试点；物流／供应链为默认候选，金融、legal operations、制造业保留题库。

移动端优先，支持逐轮语音和文字。用户自填、口述、粘贴或上传简历；LinkedIn URL 只保存，不读取；Apollo／Clay enrichment 后置。

首版建设：访谈、资料确认、研究用途选择、技能重评、简历生成及导出、求职建议、福利目录及领取、联系偏好、领域档案、问题卡与运营后台。

后续根据需求开放：针对具体岗位的深度辅导、练习和导师反馈、课程、社区、专家撮合、商业研究与收费。首版只收兴趣，不出售尚未交付的服务。

## 3. 核心流程

1. 用简历优化、技能重评和真实福利吸引用户进入。
2. 说明交付、研究用途和可跳过事项，选择语言与目标。
3. 导入现有简历或口述背景，确认系统理解。
4. 通过典型任务、实际判断、具体问题与解决经历开展访谈。
5. 确认事实，生成技能摘要、简历草稿和求职建议。
6. 编辑并复核简历，复制或下载，选择相关福利。
7. 自愿保存邮箱并选择课程、社区、专家回访等联系偏好。
8. 允许研究使用的内容进入流程、问题和领域档案；其余资料只服务本人。

行业问题成为首期的重要访谈内容。用户允许研究使用时，一段回答可以同时支撑个人简历与行业问题卡。没有研究用途授权时，相关叙述仅用于本人求职成果，不进入研究处理。

核心问题是“你做过什么、需要什么判断、哪里遇到困难”。更长的行业深访仍可分次展开，覆盖第二个问题、机器人细节或买方验证。

## 4. 渐进式采集

第一段建议 3–5 分钟：主要岗位、行业、经验与目标，先形成能力摘要。

第二段建议 5–8 分钟：典型任务、上下游、判断、一次具体问题和当前办法；允许研究的情况下形成第一张问题卡。

第三段按需补齐简历：公司显示名称、职称、任期、职责、成果、教育和证书。已有简历的人只确认缺口；没有简历的人可能需要更多时间，可分次完成。

已有完整简历者主流程目标约 10–15 分钟，需试访校准。不能承诺所有人都能在该时间内获得完整简历。每个阶段都能查看已有草稿、修改或暂停。

| 信息层 | 主要字段 | 收集规则 |
|---|---|---|
| 身份与联系 | 显示姓名、邮箱验证、可选 LinkedIn URL、地区和语言 | 邮箱服务用途说明清楚，营销独立选择 |
| 职业背景 | 公司、任期、岗位、行业、职责与经验 | 简历名字和日期由本人确认 |
| 任务与成果 | 输入、操作、判断、输出、成果案例、工具 | 每个结论关联原话或已确认简历片段 |
| 行业知识 | 流程位置、亲历范围、具体问题、频率、影响和当前办法 | 允许相应用途后才进入研究库 |
| 未来方向 | 目标岗位、地点／工作方式、学习兴趣 | 不推断健康、移民或财务状况 |
| 合作意愿 | 社区、课程信息、专家回访和参与方式 | 各自选择，真实项目出现后再确认 |

“全面”意味着关键维度有状态和来源：已确认、未知、不适用、拒答都可记录，不通过诱导回答填满字段。

## 5. 用户的结果包

### 技能重评

输出 3–5 项有具体案例支持的能力、可迁移的任务、尚缺的证据和一个下一步。区分做过、自述熟悉、想学及模型提出的候选，不给无依据的适配百分比。

### 优化简历

提供浏览器预览、直接编辑、复制纯文本、下载 DOCX 和可选择文字的 PDF。采用清楚的单列模板，各格式内容与顺序一致，不制作图片简历，不承诺通过所有招聘系统。

基础版面向一个目标方向。用户粘贴具体 JD 时，可以据此调整表述与顺序，但只使用其真实经历。第一期不抓取职位网站或自动投递。

生成流程：资料输入 → 事实台账 → 缺口追问 → 本人确认 → 内容草稿 → 用户编辑 → 事实复核 → 成稿导出。

不自动增加学历、证书、任期、职位、管理人数、AI 工具经验或业绩数字。比如“经常处理缺失交付文件”可以改为清楚的职责陈述；不能自行写成“降低 40% 成本”。

草稿可以预览和编辑。有未确认日期、占位符或事实冲突时显示需补齐内容，不误标为可投递成稿。用户可以补齐或删除不需要的段落，最终由本人检查并提交。

### 求职建议

首版提供 2–3 个有解释的岗位方向、搜索关键词、待补齐材料和资源链接。具体在招岗位必须有可核实来源、地区和更新时间；没有数据源时明确呈现为搜索方向，不生成虚构职位。

### 工具和求职福利

Muse 为已知候选来源；[Jobright.ai](https://jobright.ai/) 是用户明确指定、计划自行洽谈的合作候选。**没有确认 Jobright 的合作关系、coupon、referral 权益或接口**，首版后台先预留配置，不把它展示成已签约伙伴。

资源、推荐奖励与已确认合作优惠分别标识。按用户目标、语言、地区和实际使用条件匹配，不按未经确认的折扣价值宣传。

## 6. 奖励与合作机制

基础求职成果具有独立价值，工具福利增强吸引力。基础权益不取决于用户是否认为 AI 导致裁员、是否提供机密或是否同意营销。

福利卡说明：具体用途、地区、新老用户条件、有效期、是否绑卡或自动续费、领取步骤、失败反馈、平台是否获得 referral 收益。具体条款由运营核实，不能让模型生成。

额外研究奖励提前说明预计时间与资格，按参与过程发放；“没有遇到这种问题”也是有效回答。没有供应时只显示可用资源，不虚构库存。

合作方可以获得目标用户触达和合规允许的汇总使用指标。没有核验接口时，只记录跳转、发码或用户自报，不能宣称已激活。

合作洽谈材料包括目标人群、真实或明确标记的示例结果、试点规模、用户价值、兑换流程和汇总指标；不附个人简历或访谈。此次只做规划，未联系任何合作方。

## 7. 行业问题与领域档案

问题卡包含行业细分、地区、公司规模区间、角色、流程步骤、最近案例、频率区间、操作时间、等待时间、影响、现有办法、采用障碍、反例与来源。

裁员原因分别记录公司说法、本人观察、个人推断和未知；AI、普通自动化、重组和需求下降可以并存，行业新闻不能自动证明个人裁员原因。

领域档案包括熟悉的流程、亲自负责的边界、工具和术语、能解释的例外、问题证据和希望参与的方式。未来进行具体项目合作时再按需要核验经验及权限。

后续验证按问题组织：不同组织的经历 → 当前流程负责人确认 → 预算与数据条件确认 → 有范围的试点。一个人的想法不能直接标记为已验证需求。

## 8. 联系偏好与运营

结果页分别选择：保存和接收本人结果；课程与学习资源信息；同行社区；本人领域的研究或合作回访。

服务消息与营销分开。课程、社区和专家回访保存各自的选择、时间、版本与撤回状态。愿意接受专家回访不等于允许赞助商直接联系；具体引荐另行确认分享对象和内容。

后台按行业、职责、语言、地区、流程经验、授权与联系偏好筛选。研究者可查证据，运营人员可找允许联系的对象；不同角色只看到必要字段。

首版实现偏好管理、筛选和运营记录，不自动群发。后续发送前重新检查最新状态，旧导出名单不能覆盖新的退订选择。

## 9. 获客与信任

入口围绕具体交付：“把你的经验整理成更好的简历，并获得适合自己的求职工具资源。”模拟示例明确标识，真实用户材料取得相应允许后才展示。

渠道包括 LinkedIn 自愿求职帖与内容、行业组织、职业教练、校友群和用户分享。研究目的在入口可见，不伪装成提供现成工作。Open to Work 不证明被裁，背景由本人确认。[LinkedIn 说明](https://www.linkedin.com/help/linkedin/answer/a507508)

用户分享默认只带公共入口，不携带姓名、简历、前雇主、私密报告或访问令牌。个人报告与下载文件需要认证。

信息保护沿用[技术设计](./technical-design.md)的用途、访问控制、留存和删除链。汇总商业研究要做具体隐私审核，去掉姓名不等于匿名化。[欧盟委员会说明](https://commission.europa.eu/law/law-topic/data-protection/information-business-and-organisations/application-gdpr_en)

## 10. 首期指标与验证

首期同时关注：用户真正使用求职成果；平台获得有证据且允许用于研究的行业信息。后续联系许可单独统计。

| 指标 | 定义 |
|---|---|
| 访谈完成率 | 已确认职业摘要人数／开始访谈人数 |
| 简历价值实现 | 复制或下载确认版简历人数／进入简历流程人数；实际投递另由本人反馈 |
| 合格领域档案 | 职责、亲历流程、具体案例明确且有来源、允许研究的档案数 |
| 可用问题卡 | 包含具体事件、当前办法和影响依据；未知明确记录 |
| 独立覆盖 | 不同组织、行业细分、地区与岗位覆盖 |
| 联系许可 | 课程、社区、专家回访分别统计，邮箱验证另列 |
| 福利效果 | 展示、领取／跳转、自报成功、伙伴核验成功分别统计 |
| 体验与成本 | 手机完成、协助次数、语音纠错、每份成果及每张问题卡成本 |

没有观察到问题也是有价值的反例，不能为奖励诱导用户编造。注册数、联系方式数、研究授权数和营销授权数不能混为一谈。

首轮建议 15–20 位试用者，其中至少 5 位自述不熟悉数字工具。检查能否独立完成、简历是否准确可用、问题是否具体、福利能否兑现；再测试“简历优化”“技能重评”“工具福利”三种入口的质量和成本。这些是待检验方案，不是行业基准。

课程、社区和收费在实际需求形成后验证。第一期的开发边界见[开发方案](./development-plan.md)。
